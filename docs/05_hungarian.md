# 05. ハンガリアン法の内部処理

ファイル：`common/HungarianSolver.h/.cpp`（純粋な割り当てアルゴリズム）、`common/GatedAssignment.h/.cpp`（GNN 用のダミー拡張）

## 1. 解いている問題

n×m のコスト行列 C に対して、各行に高々1つ、各列に高々1つの要素を選び、合計コストを最小にする（線形割り当て問題）。
「1つの観測を複数のトラックに割り当てない」は、この制約（各列に高々1つ）そのものである。

GNN では「割り当てない」選択肢（未検出・誤検出）も必要なので、次節のダミー行・列で表現する。

## 2. ダミー行・列による未割り当ての表現（`solveGatedAssignment`）

N トラック・M 最明点に対し、(N+M)×(N+M) の拡張行列を作る（F = 割り当て禁止）。

|  | Z₀ … Z_{M−1} | 未検出₀ … 未検出_{N−1} |
|---|---|---|
| **T₀ … T_{N−1}** | c_ij（ゲート外は F） | 対角 = c_miss、非対角 = F |
| **未割当₀ … 未割当_{M−1}** | 対角 = c_fa、非対角 = F | すべて 0 |

- トラック i が「未検出_i」列に割り当てられる → トラック i は未検出（コスト c_miss）
- 「未割当_j」行が Z_j 列に割り当てられる → 最明点 j は未割り当て（コスト c_fa）
- 右下のダミー同士（コスト 0）は、実際に割り当てた組の数だけ余るダミーを吸収する
- 「全トラック未検出・全最明点未割り当て」という禁止要素を使わない解が必ず存在する

**未検出コストと未割り当て観測コストを別々に明示**できるのがこの形の利点である。

> 資料 p.18 の N×(M+N) 形式（未検出列だけを追加し、未割り当て観測コスト 0）は、
> c_miss' = c_miss + c_fa とすればこの (N+M)² 形式と同じ解になる（[02_step1.md](02_step1.md) の目的関数の式を参照）。
> 計算量は O(N²(N+M)) で、(N+M)² 形式の O((N+M)³) より小さいので、大規模な場合は資料の形式の方が効率がよい。
> 本サンプルは学習用として、2つのコストが行列上で見える (N+M)² 形式を採用した。

## 3. 禁止要素（ゲート外）の扱い：∞ を演算に使わない

呼び出し側は禁止要素を `HungarianSolver::kForbidden`（= +∞）で指定する。`solve()` の内部では

1. 入力に NaN / −∞ があれば `std::invalid_argument` を投げる
2. 有限要素の各行の最大絶対値の和 $B = \sum_i \max_j |c_{ij}|$ を求める
3. 禁止要素を $c_{\text{big}} = 2B + 1$ に置き換えた作業用行列で解く
4. 結果のうち元が禁止要素だったものは「未割り当て（−1）」として返す

禁止要素を使わない割り当てのコストは $[-B, B]$ に収まり、禁止要素を1つでも使う割り当ては $c_{\text{big}} - B = B + 1$ 以上になるので、
**禁止要素を使わない解が存在する限り、必ずそちらが選ばれる**。禁止要素を k 個使う解同士では k の小さい方が選ばれる。

資料 p.18 のような固定値 `blocked = 1e9` は、コストが非常に大きい場合に不足する可能性があり、また逆に必要以上に大きいと
ポテンシャルの計算で桁落ちが起きる。行列の値から必要十分な値を計算することで、どちらも避けている。

アルゴリズム内部で使う `kUnset = numeric_limits<double>::max()` は「まだ値がない」ことを表す比較専用の値で、
算術演算には使われない（下記の理由）。

## 4. アルゴリズム（`solveRowsLeCols`）

行数 n ≤ 列数 m の行列を対象とする（n > m なら転置して解き、結果を戻す）。
双対変数（ポテンシャル）u（行）, v（列）を持ち、常に**被約コスト** $c_{ij} - u_i - v_j \ge 0$ を保つ。
被約コストが 0 の要素だけを使った割り当ては最適である（相補性条件）。

行を1つずつ追加し、そのたびに次を行う。

```
行 i を仮想列 0 に置く（p[0] = i）
repeat
    used[j0] = true（列 j0 を探索木に入れる）
    i0 = p[j0]（列 j0 に割り当てられている行）
    未訪問の各列 j について：
        被約コスト c(i0, j) − u[i0] − v[j] で minv[j]（探索木から j への最短距離）を更新
        更新したら way[j] = j0（経路を記録）
    未訪問列の中で minv が最小の列 j1 と、その値 delta を求める
    探索木内の列：u[p[j]] += delta, v[j] −= delta（被約コスト 0 を保ったまま）
    未訪問の列：minv[j] −= delta
    j0 = j1
until p[j0] == 0（未割り当ての列に到達）
way をたどって割り当てを入れ替える（増加路に沿ったフリップ）
```

これは「被約コストを辺の長さとした Dijkstra 法による最短増加路の探索」と同じ構造で、
Jonker–Volgenant 法などと同系統の O(n² m) の実装である。

| 配列 | 意味 |
|---|---|
| `u[i]`, `v[j]` | 行・列のポテンシャル（双対変数） |
| `p[j]` | 列 j に割り当てられた行（0 = 未割り当て）。1始まり |
| `way[j]` | 増加路で列 j の直前の列 |
| `minv[j]` | 探索木から列 j への最小被約コスト |
| `used[j]` | 列 j が探索木に含まれるか |

`kUnset` を算術に使わない理由：内側ループでは**未訪問の全列**の `minv[j]` が有限値で上書きされるので、
`minv[j] -= delta` が `kUnset` に対して実行されることはない。また n ≤ m なので未訪問列が必ず残り、`delta` も常に有限である。

同コストの場合は厳密な `<` で比較しているので、添字の小さい列が選ばれる（結果は決定的）。

## 5. 計算量

| 処理 | 計算量 |
|---|---|
| 行1つの追加 | 最大 n 回の反復 × 各 O(m) = O(n m) |
| 全体（n ≤ m） | **O(n² m)**、正方行列なら O(n³) |
| GNN の拡張行列（N+M 次の正方行列） | O((N+M)³) |
| メモリ | 作業用行列 O(n m) + 配列 O(m) |

例：トラック20・最明点30なら 50³ = 125,000 回程度の基本演算で、1フレームあたりの負荷は小さい。
数百〜数千の目標を扱う場合は、ゲートで独立なクラスタに分割してから解く、疎行列向けの解法（オークション法など）を使う、などの工夫が必要になる。
