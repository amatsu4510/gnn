# 07. 添付資料（参考/GNN_CPP_Eigen.pdf, GNN.html）の確認結果

ページ番号は PDF の各ページ右下に印字されている番号である。

## 1. 技術的な誤り（修正して実装したもの）

| # | 箇所 | 資料の記載 | 問題 | 本サンプルでの対応 |
|---|---|---|---|---|
| 1 | p.7 マハラノビス距離 | $d^2 = \mathbf{r} S^{-1} \mathbf{r}^\top$、r = 観測値 − 予測観測値 | r を列ベクトル（2×1、後半のコードの `Vector2d`）とすると、$\mathbf{r} S^{-1}$ は (2×1)(2×2) で定義できない | $d^2 = \mathbf{r}^\top S^{-1} \mathbf{r}$ とした。コードは `y.dot(llt.solve(y))`（資料 p.17 のコードはこちらと一致しており正しい） |
| 2 | p.16 `predict(Track&, double dt, const M4& Q)` | Q を固定の引数として受け取る（「Q は dt に応じて設計」とも書かれている） | Q を外から固定値で渡す設計だと、フレーム間隔が変わったときに予測の不確かさが正しく増減しない（課題のテストケース12「フレーム間隔が一定ではない」で問題になる） | `KalmanFilter::processNoise(dt)` で Δt から毎回 Q を計算する |
| 3 | p.20 `update()` | カルマンフィルタの更新関数の中で `++t.hits; t.misses = 0;` | 状態推定とトラック管理の責務が混ざっている（課題の「GNN、カルマンフィルタ、トラック管理が過度に依存しない構造」に反する） | `KalmanFilter::update()` は (x, P) の更新のみ。対応回数は `Track::update()`、確定・削除の判断は `TrackManager` |
| 4 | p.10 / p.15 確定条件とデータ構造 | 「直近5回中3回対応で確定」と書かれているが、`Track` は累計の `hits` しか持たない | 累計回数では「直近 N 回中 M 回」を判定できない | `std::deque<bool> history_` で直近 N 回の対応履歴を保持 |
| 5 | p.10 トラック管理、HTML の「4. 継続追跡とライフサイクル」 | 仮トラックの削除条件・遷移がない | 誤検出から生成された仮トラックが削除されず増え続ける | 仮トラックのうちに未検出が N−M 回を超えたら削除（確定不能になった時点） |

## 2. 誤りではないが注意が必要な点

| # | 箇所 | 内容 | 対応 |
|---|---|---|---|
| 6 | p.17 ゲート `d2 <= 9.21`（99%） | 値は自由度2のカイ二乗分布の99%点として正しい（資料にも「説明用」とある）。ただし多数のフレーム・目標では正しい観測がゲート外になる回数が無視できず、実験では 100 回中 12 回トラックが分裂した | 既定値を P_G = 0.999（13.82）にした。閾値は −2 ln(1−P_G) で計算（[06](06_parameters_and_limits.md)） |
| 7 | p.18 `blocked = 1e9` | 固定の大きな値は、コストの桁によっては不足したり、逆に桁落ちを起こしたりする可能性がある | 禁止要素は +∞ で受け取り、行列の値から安全な有限値（2B+1）を計算して置き換える（[05](05_hungarian.md)） |
| 8 | p.18 N×(M+N) 行列、未対応観測コスト 0 | 正しい。解に影響するのは c_miss + c_fa の和だけなので、c_fa = 0 としても一般性を失わない | 学習用に、両方のコストが明示される (N+M)×(N+M) 形式を採用し、等価性を [02](02_step1.md)・[05](05_hungarian.md) で説明 |
| 9 | p.17 コメント `// Euclidean alternative: (z.pos - t.x.head<2>()).norm()` と `d2 <= 9.21` | ユークリッド距離 [px] に切り替えた場合、閾値 9.21（d² 用、無次元）や未検出コスト 10 はそのまま使えない | STEP 1/2（px）と STEP 3（d²）で `TrackingConfig` を分け、単位をコメントに明記 |
| 10 | p.16 `(F * t.x).eval()` | 行列積は Eigen が自動で一時オブジェクトに評価するので `.eval()` は不要（害はない） | `x = F * x;` とし、`.eval()` が本当に必要な場面（`P = 0.5 * (P + P.transpose()).eval()`）と区別して説明（[04](04_step3.md)） |
| 11 | p.15 `Detection` | 時刻がない | 課題の要求に合わせ `timestamp` を追加。Δt は時刻の差から計算 |
| 12 | p.7 マハラノビス距離のコスト | d² のみのコストは、S の大きいトラックが有利になる（資料にも「尤度ベースのコストでは追加項も使用」とある） | 課題の指定どおり d² を使い、限界と改善方法（d² + ln\|S\|）を [06](06_parameters_and_limits.md) に記載 |
| 13 | HTML「1. 処理フロー」 | 「状態更新」で終わり、トラック管理（生成・削除）がない | 本サンプルのフロー図には生成・状態遷移・削除を含めた（[01](01_design.md)） |

## 3. 正しいことを確認した記載

- p.5 の NN と GNN の例（貪欲法 10、GNN 4）→ テスト「資料の例_貪欲法では最適にならない」
- p.8 のコスト行列の値（5.83, 2.83, 11.18, 18.03、合計 19.84）→ HTML の座標から再計算して一致。テスト「資料p8の例_合計19.84px」
- p.18 の例（T1→Z2, T2→Z1）→ テスト「ダミー拡張_資料の例」

- p.20 の Joseph 形式の式 → 正しい
- HTML の NN/GNN 比較・ゲーティングのデモ（未割当トラックのコスト = ゲート半径+1、未割当観測 = 0）→ 和がゲート半径より大きいので、ゲート内の組は常に割り当てる設定として正しい
