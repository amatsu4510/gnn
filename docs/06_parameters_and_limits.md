# 06. パラメータの意味と調整方法、アルゴリズムの制約と改善方法

## 1. パラメータ一覧

### STEP 1 / STEP 2（`TrackingConfig.h`）

| パラメータ | 既定値 | 意味 | 調整の目安 |
|---|---|---|---|
| `gateDistance` | 30 px | ゲート半径（基準点からの距離） | 1フレームの最大移動量（STEP 1）または最大予測誤差（STEP 2）＋ 観測ノイズの3σ。大きすぎると誤検出を拾い、小さすぎると目標を見失う |
| `missCost` | 15 px | 未検出コスト | `missCost + falseAlarmCost` が実質の割り当て閾値。ゲート半径と同じにすると、ゲートだけで割り当ての可否が決まる |
| `falseAlarmCost` | 15 px | 未割り当て観測コスト | 同上 |
| `alpha` | 0.7 | α-β の位置ゲイン（STEP 2） | 大きいほど観測に追従、小さいほど平滑化 |
| `beta` | 0.3 | α-β の速度ゲイン（STEP 2） | 大きいほど速度変化に素早く追従するがノイズに弱い。安定条件は 0 < α < 2, 0 < β < 4 − 2α（実用上は 0 < α < 1） |
| `confirmHits` / `confirmWindow` | 3 / 5 | 直近5回中3回対応で確定 | 誤検出が多い環境では M を大きく（確定が遅れる代わりに誤確定が減る） |
| `maxCoastingFrames` | 5 | 連続5回未検出で削除 | 一時的な未検出（遮蔽）の最大長より大きく。大きすぎると消失した目標が長く残り、誤検出を拾いやすい |

### STEP 3（`TrackingConfig.h`）

| パラメータ | 既定値 | 意味 | 調整の目安 |
|---|---|---|---|
| `gateProbability` | 0.999 | 正しい観測がゲート内に入る確率 P_G | 閾値 γ = −2 ln(1−P_G)。下記参照 |
| `missCost` / `falseAlarmCost` | 6.908 / 6.908 | d² 単位のコスト | 和を γ（13.82）と同じにしている |
| `processNoiseDensity` (q) | 200 px²/s³ | 加速度雑音の強さ | 目標の加速度の大きさを a [px/s²] とすると q ≈ a²·Δt 程度が目安。大きいほど機動に強いがゲートが広がる |
| `measurementNoiseStd` (σ_r) | 1.0 px | 観測ノイズの標準偏差 | **実データの最明点の位置誤差に合わせる**。過小だと正しい観測がゲートから外れ、過大だとゲートが広がりすぎる |
| `initialVelocityStd` | 100 px/s | 新規トラックの速度の不確かさ | 想定する最大速度程度。小さすぎると2回目の観測がゲートから外れる |
| `confirmHits` / `confirmWindow` / `maxCoastingFrames` | 3 / 5 / 5 | STEP 2 と同じ | |

### ゲート確率 P_G を 0.999 にした理由

資料（p.17）の 9.21 は P_G = 0.99 に相当し、値としては正しい。しかし「正しい観測が 1% の確率でゲート外になる」ということは、
2目標 × 30フレームの追跡では $1 - 0.99^{60} \approx 45\%$ の確率でどこかで1回は正しい観測がゲートから外れる。
外れた観測は未割り当てとなって新しい仮トラックになり、元のトラックと観測を奪い合って**トラックが分裂**する。

実験（2目標の交差シナリオ、シード1〜100、プロジェクト外の計測用プログラムで測定）：

| P_G | γ | 交差角 43.6° の ID維持 | トラックの分裂 |
|---|---|---|---|
| 0.99 | 9.21 | 95 / 100 | 12 / 100 |
| 0.999 | 13.82 | 100 / 100 | 0 / 100 |
| 0.9999 | 18.42 | 100 / 100 | 0 / 100 |

一般に P_G は 0.99〜0.9999 程度が使われる。誤検出が多い環境では、ゲートを広げると誤検出を拾う確率も上がるので、
誤検出密度と合わせて調整する。

### 調整の進め方（実データに適用する場合）

1. 静止した目標や既知の動きの目標で、最明点の位置のばらつきを測り σ_r を決める
2. 目標の最大速度・加速度から `initialVelocityStd` と q を決める
3. NIS（d² の平均、観測が2次元なら理想値 2）を確認する。大きすぎれば q か σ_r が小さすぎ、小さすぎれば大きすぎる
   （テスト「KF_一貫性_NISの平均が自由度2に近い」がこの考え方の例）
4. 誤検出の量を見て、確定条件（M/N）と削除条件を調整する

## 2. 目標の接近・交差と GNN の限界

GNN は「各フレームで、定義したコストの合計が最小になる割り当て」を求める。これは**そのフレームのコストに対する最適解**であって、
正しい対応である保証はない。特に2目標が近づくと、次の理由で ID が入れ替わることがある。

1. **各フレームで1つの決定しかしない（ハード決定）**：2つの観測がどちらの目標か曖昧でも、どちらか一方に決めて状態を更新する。
   誤った決定をすると、そのトラックの位置・速度が別の目標の方へ引っ張られ、以後その誤りを修正する手段がない。
2. **過去の決定をやり直さない**：数フレーム後に「あの時は逆だった」と分かる情報が得られても、GNN は戻れない。
3. **位置と速度しか見ていない**：輝度などの特徴を使わないため、運動だけで区別できない状況では原理的に区別できない。

実験（2目標が y 方向に ±v で近づいて交差、x 方向 100 px/s、σ_r = 1 px、シード1〜100）：

| 交差角 | STEP 2（α-β）の最終ID維持 | STEP 3（KF）の最終ID維持 |
|---|---|---|
| 43.6°（v = 40 px/s） | 100 / 100 | 100 / 100 |
| 22.6°（v = 20 px/s） | 100 / 100 | 100 / 100 |
| 11.4°（v = 10 px/s） | 86 / 100 | 90 / 100 |
| 5.7°（v = 5 px/s） | 78 / 100 | 82 / 100 |
| 3.4°（v = 3 px/s） | 65 / 100 | 64 / 100 |

交差角が小さいほど、2目標の相対移動量（1フレームあたり 2v·Δt）が観測ノイズに対して小さくなり、
長い時間「どちらがどちらか分からない」状態が続くため、ID維持率は 50%（ランダム）に近づいていく。
カルマンフィルタにしても、運動モデルで区別できない状況は解決しない。

デモの `approach` シナリオ（交差角 3.4°、シード 8）は STEP 2・STEP 3 ともに ID が入れ替わる例で、
テスト「8_浅い角度の接近ではIDが入れ替わり得る（GNNの限界）」でこの限界を確認している。
X字に交差する `crossing` シナリオ（交差角 約62°）では両STEPとも ID を維持する。

なお、交差の瞬間に1フレームだけ観測が入れ替わって割り当てられ、次のフレームで元に戻ることもある（一時的な誤対応）。
`IdConsistency` は「最初と最後のトラックID」と「別IDに対応したフレーム数」を分けて集計している。

## 3. その他の制約

| 制約 | 内容 |
|---|---|
| 1目標1観測の仮定 | 1つの目標から複数の局所最明点が出る（資料 p.13）と、余った最明点から仮トラックが生成される。近い最明点の統合（クラスタリング）を前段で行う必要がある |
| 背景の固定輝点 | 静止した輝点は「速度0の目標」として確定トラックになる。速度による除外や背景差分が必要 |
| 等速モデル | 急な加減速・旋回では予測が外れる。q を大きくするとゲートが広がり誤対応が増える |
| d² だけのコスト | 不確かさの大きいトラック（生成直後・Coasting）は S が大きく d² が小さくなるため、遠い観測でも安く見える。生成直後の仮トラックが確定トラックの観測を奪うことがある |
| 誤検出から生まれた仮トラック | 未検出のたびに S が大きくなり（overall シナリオで σ ≈ 30 px）、ゲートが広がって本物の観測を奪いやすくなる |
| 画像の端 | 画像外に出た目標も予測で Coasting が続く。画像範囲外の予測位置で削除する処理はない |
| 計算量 | 拡張行列は (N+M)² なので、数百以上の目標・観測では重くなる |

## 4. 改善方法

| 改善 | 内容 |
|---|---|
| 尤度ベースのコスト | コストを $d^2 + \ln\lvert S \rvert$（負の対数尤度）にすると、不確かさの大きいトラックが不当に有利になるのを防げる（資料 p.7 の「追加項」）。未検出・誤検出コストも検出確率 P_D・誤検出密度 λ から $-\ln(1-P_D)$ や $-\ln\lambda$ のように導出できる |
| JPDA | 曖昧な観測を確率で重み付けしてすべて使う。ハード決定による誤りの影響が小さい |
| MHT | 複数の対応仮説を数フレーム保持し、後から最も尤もらしいものを選ぶ。交差に強いが計算量が大きい |
| 特徴量の利用 | 輝度（本サンプルでは保持のみ）や形状をコストに加え、運動で区別できない場合の手がかりにする |
| IMM | 等速・旋回など複数の運動モデルを切り替えて機動目標に対応する |
| クラスタ分割 | ゲートでつながったトラックと観測のグループごとに割り当て問題を解き、計算量を減らす |
| N×(M+N) 形式 | 未割り当て観測コストを未検出コストに含め、拡張行列を小さくする（[05_hungarian.md](05_hungarian.md)） |
| 削除条件の追加 | 共分散が大きくなりすぎた（位置σ がしきい値超え）・画像外に出た、などでも削除する |
| 起動ロジック | 2フレームの最明点から速度ゲートを使って仮トラックを作る（2点起動）と、誤検出由来の仮トラックが減る |
